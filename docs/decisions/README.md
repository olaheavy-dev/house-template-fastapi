# Decisions

Hard-to-reverse choices this template makes for every project that uses it get a numbered record in this folder. The format is the base layer's: [0001 Record decisions](https://github.com/olaheavy-dev/house-template-base/blob/main/template/docs/decisions/0001-record-decisions.md) (Context, Decision, Consequences, Alternatives considered, Sources). Easily reversible choices get one line in the register below. Accepted records aren't rewritten: a new record supersedes an old one. A record whose status is Proposed lists its open questions and becomes Accepted only when the founder decides them.

These records describe the template repository itself. They are not copied into generated projects (the template's `_subdirectory` is `template/`). A test (`tests/test_decisions.py`) fails if a record file is missing from the table below, or a row has no file.

| 2026-11-12 | Redaction also covers the tool definitions and output schemas a call offers, under both frameworks (`walk_definition` and `with_schema` in `app/llm/core/redaction_data.py`): descriptions, titles, property names, allowed and example values are scanned; a name, a JSON Schema type, format, `$id` or `$ref`, and the names under `$defs`, are left alone. A Pydantic schema with something to replace is sent as a subclass whose `model_json_schema()` is the redacted one, and the parsed answer is turned back into the caller's class. Record 0006 listed the message list as the scope; it is not rewritten, this widens it (#112 review) | A provider reads a definition as it reads a message, so a value in a generated description or an `enum` was sent as it was. Identifiers stay because a provider refuses a call whose names it cannot read. The subclass keeps each SDK's own conversion (OpenAI's strict schema, Anthropic's output format) instead of rebuilding it per provider. Nothing changes when nothing matches: the same objects are sent. Cost: a schema rule that holds personal data (`pattern`) stops matching |
| 2026-11-12 | A streamed MAF call settles from the usage at its end; one the consumer stops reading (closed, or dropped and collected) is recorded as failed and keeps its reservation; a cancelled one stays reserved; a failure after output keeps the reservation even for a rejection kind. The budget's stream is its own async generator, so a dropped stream still settles. Under LangChain the redacting wrapper now closes its inner stream when its consumer stops, instead of leaving it to garbage collection. A structured answer that does not parse into its schema is the core's `SchemaMismatch` (502, settled at cost) under both frameworks; with LangChain and `LLM_REDACTION=off`, `gateway.model()` is the provider's model and its parser's pydantic `ValidationError` stays a 500 (#35 PR 3) | Neither OpenAI nor Anthropic documents billing for a disconnected stream and no usage arrives then, so keeping the reservation never under-records; MAF's docs say a bare `break` has no deterministic cleanup, so the gateway must not rely on callers. Mapping every pydantic `ValidationError` to the 502 would also hide the app's own bugs, so LangChain's is converted only inside `with_structured_output`, where it can only come from the answer |
| 2026-11-12 | The MAF step limit is counted by our own code, as record 0003 says: the gateway's client puts a `StepRun` into each run's options (MAF copies the options once per run but keeps the object, measured on agent-framework-core 1.25.0), the budget middleware counts each model call against the core's `StepLimit`, removes it before the provider, and sends the last allowed call with `tool_choice="none"`; the run's result carries `step_limit_reached` (additional properties, so an Agent's response has it too; a stream gets it in one last empty update) and the run is logged once. `max_iterations` = N - 1 stays as the backstop, so MAF never makes call N + 1. Replaces the budget middleware's `final_only` switch (#35 PR 4) | MAF documents no per-run cap on model calls and no way to make only the last call tool-free (its own limits do it, uncounted and unflagged), and `max_iterations` is a client setting shared by every agent on it; per-run state through the options is the one path every model call of a run sees |
